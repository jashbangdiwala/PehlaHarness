# Build Check before moving on
0 Safety net Commit everything. Tag v0. Confirm .gitignore covers ea.db, allowed_id.txt, .venv. Add a CLAUDE.md (text below). git status clean; pytest green; git ls-files shows no ea.db
1 Restructure Move, don't rewrite: main.py to channels/telegram.py, egress.py to core/gateway.py, events.py to core/events.py, tests to tests/. Create agents/ea/ with the system prompt in prompts/system.md. Model name and DB path move to one config.py. Add an import-rule test. Bot replies exactly as before; pytest green, including the test that fails if core imports agents
2 History EA sends the last N turns (read from events, domain='ea') with each call. Today every message is answered with no memory of the previous one. Say "my name is Jash", then ask "what's my name?"
3 Tool contract core/tools.py: a tool is a name, a description, a JSON schema and a Python function. gateway.ask() accepts tools and returns either text or tool calls. Unit test with a fake tool; one live call where the model asks for the tool
4 Loop core/loop.py: call model, run any tool calls, feed results back, repeat. Stops on a text answer or max_steps=6. Tool errors go back to the model as text. Every step is an event with parent_id. Tests run against a stubbed gateway (no network): happy path, tool error, max-steps cut-off
5 EA tools In agents/ea/: log_food, log_time, goals (add, list, review against time logs). EA owns its tables (ea_food, ea_time, ea_goals). Each tool unit-tested; one Telegram message triggers two tools and rows appear
6 Policy core/policy.py: per-agent tool allowlist, checked before every tool runs; refusals are logged. Test: a tool not on EA's list is refused and an event is written
7 Trace python -m core.events trace <id> prints one message's tree: model calls, tool calls, tokens, seconds. You can read a full run top to bottom without opening SQLite
8 Ship Run the exit test. Write the one-pager and docs/adr/001-repo-split.md. Tag v1. Exit test passes three times in a row

CLAUDE.md starter (paste into the repo root)

# Harness rules
- Layout: channels/ agents/ core/ evals/ models/ lab/ docs/ tests/
- core never imports agents. Agents never import each other.
- Every model call goes through core/gateway. Every tool run goes through core/policy.
- Each agent owns its prompts/, tools/, tables and evals/.
- Secrets come from keyring only. Never print or log them.
- One step per session. Tests first. No behaviour change outside the step.
- Stop and show the diff before committing.

Prompt pattern for each step

Read CLAUDE.md. Do step <N> of the Phase 1 plan only: <paste the Build cell>.
Done means: <paste the Check cell>.
Write or update tests first. Do not touch anything outside this step.
Show me the diff and the test output, then stop.

Do alongside (sets up Phase 2)

  1. Save 20 real messages you send the EA, each with what the right outcome was. That is your golden set; evals cannot start without it.
  2. Note every bad reply in one line: what you asked, what went wrong. That is your error analysis, already started.
  3. Learning: the Phase 1 block in harness-learning-plan. You are done when you can draw the loop from memory and say what goes into context each turn.
