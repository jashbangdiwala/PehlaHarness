2. Target shape

 channels/            telegram · cli
     │
 agents/     ea        game        redteam      (later ones)
     │        └──────────┴────────────┘
     │        agents import core, never each other
 core/       gateway · loop · memory · policy · decide · events
     │
 evals/      reads events, scores every agent, gates every change

 models/                  fine-tune open models from Hugging Face; publishes to the Hub
 lab/llm-from-scratch/    Raschka book; isolated, imports nothing from above
 docs/                    ADRs, threat model, reports

Split rules (these are what keep it clean):

  1. core never imports an agent. Agents never import each other.
  2. Each agent folder owns its prompts/, skills/, tools/, evals/, README, and its own memory namespace (the domain column you already have).
  3. Every model call goes through gateway. Every action goes through policy. One place to measure cost, one place to enforce security.
  4. lab/ is a separate world. At most it hands over a trained model file.
  5. models/ reads training data exported from events and publishes a finished model. The harness only ever reaches that model through gateway, like any other model.

3. Core modules

Module Job Think of it as
gateway Redact, route to a model, cache, cap spend The bank's payment gateway
loop Think, act, observe, repeat until done; retries and stop rules A workflow engine
memory Store, retrieve, consolidate overnight ("dreaming") Notebook plus a nightly tidy-up
policy What each agent may do; what needs your approval Entitlements
decide Jev client: typed decisions with a confidence score Gut call (fast) vs the LLM's deliberate thinking (slow)
events Trace of every step plus cost ledger Audit log
evals Scorecards and a regression gate Test suite for behaviour

4. Agents

Agent Does Proves
ea Telegram second brain: goals, food, time-allocation feedback Tools, memory, daily real use
game Plays a browser game. LLM plans, Jev picks each move Perceive, decide, act loop; System 1 / System 2 split; cost per game
redteam Attacks ea and game with injections and bad inputs Security depth, multi-agent

Game proposal: start with 2048 in a sandboxed browser. It is visual for the demo, the board can be read as text (cheap), and the score is the eval. Screenshot-only play is the stretch goal.

9. Model track (Hugging Face)

Lab teaches how a model works inside. This track teaches the job people actually do: take an existing open model, adapt it, prove it, publish it. Start small; each step reuses the path the one before it built.

Step Build Head-to-head eval Needs
M1 Use Pull 2 to 3 Hub models, read their model cards and licences, run them Same EA golden set, scored against your current model Phase 2
M2 Classifier Fine-tune a small model to flag prompt injection, using red-team attacks as training data Your model vs Jev vs an LLM: accuracy, cost, latency Phase 4
M3 Embeddings Pick or tune the embedding model behind memory search Retrieval eval before and after Phase 5
M4 Task model LoRA fine-tune of a small open LLM for one EA job (e.g. turning a food message into a structured log) Small tuned model vs big model: quality, cost per task Phase 3, plus enough EA logs 
 events ──export──▶ dataset ──train (rented GPU)──▶ model ──▶ Hub (public)
                       │                              │
                    scrub + review                 gateway ──▶ agents

Rules for this track:

  1. Never publish raw EA logs. They are your food, time and goals. Public datasets are synthetic or red-team generated, then redacted and read by you before upload.
  2. Every published model ships with a model card: what it is for, training data, eval numbers, known failures, licence.
  3. Every training run is logged: GPU hours, cost, config, result. GPU spend is its own budget, outside the $20/month inference cap.
  4. Check each base model's licence and origin before using it (your open-weight, US-based rule).

Not in scope for now: quantizing and hosting models yourself. Add it as M5 if you want the full lifecycle later.

10. What every phase ships

  1. Working demo (video or Telegram screenshot).
  2. Scorecard from the eval runner.
  3. One-page write-up: what I built, what broke, what I measured, how this changes at bank scale.
  4. One ADR for the main decision.

That four-part set is the interview answer for the track.

11. Open items

  • Jev access and price: figures are vendor-reported and it launched as early access. Confirm you can get a key inside the $20/month cap.
  • Whether Jev accepts images is unverified. The plan assumes the harness turns the screen into a text state first.
  • Serving for M4: a classifier or embedding model is small enough to run on the MacBook's CPU, but a tuned LLM needs a hosted endpoint billed by the hour. Price it when you get there.
